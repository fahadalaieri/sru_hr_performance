# بيئة تطوير من قاعدة فارغة

> هذا المجلد يجيب عن سؤال واحد: **كيف يشغّل مطوّر جديد المشروع على قاعدة Supabase فارغة خاصة به؟** — دون الوصول إلى قاعدة الإنتاج، ودون اختلاق بيانات تبدو حقيقية.

## الخطوات

1. أنشئ مشروع Supabase جديدًا (المنظمة المجانية تكفي) وانسخ `.env.local.example` إلى `.env.local` واملأ: `NEXT_PUBLIC_SUPABASE_URL`، `NEXT_PUBLIC_SUPABASE_ANON_KEY`، `SUPABASE_SERVICE_ROLE_KEY`، `DATABASE_URL` (Session pooler — الاتصال المباشر IPv6 فقط)، ثم أضف `DEV_ADMIN_EMAIL` و`DEV_ADMIN_PASSWORD` لحساب المشرف التطويري.
2. طبّق الهجرات:
   ```bash
   node scripts/dev-seed/migrate.mjs apply-continue
   ```
   يتخطّى الهجرات الواردة في `non-replayable.json` (انظر أدناه) ويُبلّغ عنها كمتوقَّعة؛ أي فشل آخر يُطبع تحذيرًا وينتهي بخروج غير صفري.
3. ابذر بيانات التطوير:
   ```bash
   node scripts/dev-seed/seed-dev.mjs
   ```
   آمن للتكرار؛ يُنشئ فقط ما ليس موجودًا ويُبلّغ عن كل خطوة.
4. شغّل `npm run dev` وادخل باسم المستخدم `admin` وكلمة المرور التي وضعتها.
5. (اختياري) اختبارات التكامل على قاعدتك: `npm run test:integration` (ومع `INTEGRATION_BASE_URL=http://localhost:3000` لتشمل مسارات التصدير).

كلا السكربتين **يرفض الاشتغال** إن أشار `DATABASE_URL` إلى مشروع الإنتاج.

## ماذا يبذر `seed-dev.mjs`؟

| ما يُنشأ | لماذا | مصدره |
|---|---|---|
| حساب `super_admin` (ملف `DEV-0001`، اسم مستخدم `admin`) | لا يمكن فتح `/admin` ولا إنشاء أي شيء بدونه؛ لا هجرة تنشئ حسابات | `DEV_ADMIN_EMAIL`/`DEV_ADMIN_PASSWORD` من `.env.local` عبر Admin API؛ الربط عبر `pending_role_assignments` + المحفّز القائم |
| دورة تقييم واحدة للسنة الحالية (`دورة التطوير <السنة>`) | الترقيات والمكافآت والمعايرة والأهداف والمهام كلها تتطلب `cycle_id` إلزاميًا، وبدونها تظهر رسائل «لا توجد دورات» | قيمة اختبارية واضحة الاسم |
| مستويات الهيكل الأربعة + منصب الجذر وأبناؤه المباشرون | شاشة الهيكل التنظيمي والتسكين فارغتان تمامًا بدونها | **مشتق** من شجرة `org_units` الحقيقية (الهجرات تحملها): منصب لكل وحدة، بنفس اسمها |
| سلّم «عام» للمسار الوظيفي (درجة → الدرجة التالية) | شاشة المسار الوظيفي فارغة بدونه | **مشتق** من `job_titles` في عائلة «عام» (الهجرة 20260720000001 تحملها)؛ يربط الدرجات المتتالية حين تكون الدرجة بمسمى واحد فقط |

كل ما يُبذر إمّا مشتق من بيانات مرجعية حقيقية تحملها الهجرات، أو قيمة اختبارية باسم يصرّح بذلك. **لا يُختلق** راتب ولا جدارة ولا موظف.

## الهجرات التي لا تُعاد على قاعدة فارغة (`non-replayable.json`)

عشر هجرات بيانية تفشل على أي قاعدة غير قاعدة الإنتاج. ثماني منها تُدرج صفوفًا بمعرّفات UUID ولّدتها قاعدة الإنتاج عشوائيًا (لأن `job_titles` أُدرجت في 20260720000001 بلا معرّفات صريحة)، واثنتان تستخدمان الأسماء لكنهما تفترضان حالة بيانات أنشأتها هجرات سابقة من المجموعة نفسها. النتيجة على قاعدة فارغة:

- `career_path` بلا الـ157 رابطًا الحقيقية (يعوّضها السلّم «عام» المشتق جزئيًا).
- `job_title_competencies` فارغ (1196 ربطًا في الإنتاج) — فشاشات الجدارات حسب المسمى الوظيفي فارغة.
- `org_structure_positions` بلا الـ49 منصبًا الحقيقية (يعوّضها البذر المشتق جزئيًا).
- الجزء **الهيكلي** من 20260829000001 (جدولان وعمودان وست سياسات) يجب تطبيقه يدويًا لأنه مدمج مع الجزء البياني الفاشل؛ لا يُسجَّل.

سجل Supabase (`schema_migrations`) مفتاحه الإصدار لا اسم الملف، فحين ينجح أحد الملفين يُسجَّل الإصدار ويبدو توأمه الفاشل «مُطبَّقًا». هذا بالضبط ما حدث في قاعدة التطوير: ثلاثة من الهجرات الهيكلية (`20260727000001`، `20260829000001`، `20260831000002`) فشلت، لكن السجل يعدّ إصداراتها مطبَّقة بفضل توائمها الناجحة — ولولا التحذير الذي يطبعه المشغّل الآن لظهرت القاعدة مكتملة. اختبار `migrations-ledger` يفشل عند ظهور أي تكرار **جديد** خارج هذه القائمة. **الحل بيد صاحب الإنتاج**: إعادة ترقيم أحد الملفين إلى إصدار فريد، ثم إدراج الإصدار الجديد يدويًا في سجل الإنتاج (`INSERT INTO supabase_migrations.schema_migrations(version, name)`) حتى لا يحاول Supabase CLI إعادة تشغيله هناك.

### ما يجعلها قابلة للإعادة — وهو بيد صاحب الإنتاج وحده

التصدير **بالأسماء** من قاعدة الإنتاج (العائلة + المسمى، اسم الوحدة، اسم الجدارة) ثم إعادة كتابة كل هجرة كـ `INSERT ... SELECT` بالاسم. لا يمكن إنجاز ذلك من هذا المستودع لأن الأسماء المقابلة للمعرّفات ليست فيه؛ ولا يصح اختلاقها. حين يتوفر التصدير، تُضاف هجرة جديدة بالأسماء وتُنقل الهجرات العشر إلى أرشيف، وتُحذف من `non-replayable.json` — فيفشل اختبار `migrations-ledger` تلقائيًا إن بقيت واحدة غير مسجَّلة دون مبرر.
